# 六类主数据对象卡与归属图

> 全部示例为虚构。业务表统一含 id(UUID)、org_id、site_id、created_at、created_by、updated_at、deleted_at（软删）。
> owner 具体角色为保守示例，需按客户标定；判定规则（查重两类/30天撤销等）按客户原文，不在此改动。

## 对象卡（6 张）

### 1. 会员企业
- 定义：平台服务的法人/组织主体（Party 主数据）。
- owner：会员运营 / 招商负责人[需标定]。
- 必填字段：`ent_id`、`ent_name_c`、`uscc_c`（可空但唯一）、`ent_status_c`（枚举 ACTIVE/INACTIVE/PENDING）。
- 上游：入驻申请、CRM、批量导入。
- 下游：CRM 客户、商机归属、资源匹配、驾驶舱统计。
- 边界：空信用代码不触发唯一；软删行不计入质量分母但审计保留。

### 2. 联系人
- 定义：隶属于会员企业、承担业务联络的自然人。
- owner：会员运营 / CRM 管理员[需标定]。
- 必填字段：`contact_id`、`ent_id`（外键）、`contact_name_c`、`mobile_c`（敏感，默认打码）。
- 上游：企业提交、名片录入、导入。
- 下游：通知、商机跟进、账号关联。
- 边界：手机号只验 11 位数字形态，不验真伪；明文查看需更高权限且留痕。

### 3. 能力卡
- 定义：会员企业可对外提供的产品/服务/资源能力描述。
- owner：内容运营 / 资源对接负责人[需标定]。
- 必填字段：`cap_id`、`ent_id`、`cap_name_c`、`cap_status_c`。
- 上游：企业自报、运营审核。
- 下游：资源匹配、商机推荐、官网展示。

### 4. 需求卡
- 定义：会员企业发布的采购/合作/资源需求。
- owner：资源对接 / 招商负责人[需标定]。
- 必填字段：`demand_id`、`ent_id`、`demand_name_c`、`demand_status_c`。
- 上游：企业发布、运营录入。
- 下游：商机生成、资源匹配、看板。

### 5. 商机
- 定义：由需求/能力匹配产生、有明确跟进主体与阶段的业务机会。
- owner：招商业务员 / 销售负责人[需标定]。
- 必填字段：`opp_id`、`ent_id`、`opp_stage_c`（枚举）、`owner_user_id`；**金额以「分」存整数**，AI 不计算金额。
- 上游：需求卡/能力卡匹配、业务员录入。
- 下游：销售工作台、驾驶舱、漏斗统计。

### 6. 活动参与记录
- 定义：会员企业/联系人参与平台活动的事实记录。
- owner：活动运营负责人[需标定]。
- 必填字段：`part_id`、`ent_id`/`contact_id`、`event_id`、`join_status_c`。
- 上游：小程序报名/签到、官网。
- 下游：活跃度分析、精准运营、驾驶舱。

## 归属图（唯一 System of Record）

```
              会员数据中台（受管对象）
   ┌──────────┬──────────┬──────────┬──────────┬──────────┐
  会员企业    联系人    能力卡    需求卡     商机     活动参与
    (根)      (挂企业)  (供给)    (需求)   (供需对接) (互动轨迹)
    │           │         │         │         │          │
  会员运营   会员运营   内容运营   资源对接  招商业务员  活动运营
   /招商     /CRM管理员 /资源对接  /招商     /销售负责人
  唯一SoR    唯一SoR    唯一SoR    唯一SoR   唯一SoR     唯一SoR
```

**SoR 规则**：一个对象被两个来源写入时，指定唯一权威源（SoR），另一来源降级为 contributor/只读；冲突以 SoR 为准，并在字段字典/归属图登记。
**软删除**：`deleted_at` 非空 → 质量三率与统计分母只计 active 记录，但行不物理删除，审计可查；恢复删除也须留痕。
